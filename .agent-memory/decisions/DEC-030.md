# DEC-030: the catalogue lives in game-core; client systems arrive via a provider

**Date:** 2026-08-09
**Category:** decisions
**Related Docs:** docs/03_runtime_modes.md#D03-S5.2, docs/04_entity_component_model.md#D04-S4.4, docs/02_technical_architecture.md#D02-S5.6

**Status:** active

## Summary
`SystemSlot` holds all 27 slots of D04-S4.4 with their phase, module and mode filter;
`SystemSetFactory.forMode` filters it and asks a `SystemProvider` to construct each surviving slot.
`CoreSystemProvider` builds the `game-core` systems; the six `game-client` slots are contributed by
a provider the client passes in.

## Details
D03-S5.2 writes the schedule as one list of class names, six of which live in `game-client`.
`game-core` sits below the client in the layer order (D02-S5.6), so naming them there is the
dependency cycle layering exists to make unrepresentable. The split is: the **catalogue and its mode
filter** stay in `game-core`, where they remain the single description of causality D04-R13 wants;
**construction** is delegated.

Providers are consulted in order and the first non-null wins, so a client passes
`(clientProvider, coreProvider)` and a dedicated server passes the core provider alone.

**Null means "not implemented", and that is not an error.** Eighteen of the 27 slots are unwritten.
`forMode` leaves them out and logs the list once at startup. Refusing to boot until all 27 exist
would mean the schedule could not be exercised until the last of them landed — and the point of
building it now is that a process can run the nine that do.

**Order is structural, and asserted anyway.** `SystemSlot`'s declaration order is the catalogue
order, so filtering cannot reorder. `verifyOrder` checks it regardless, and `forMode` additionally
refuses a system whose `order()` disagrees with the slot it filled — the one way a provider could
still produce a schedule `World.registerSystems` would sort differently.

## Rationale / Context
The obvious implementation is a `switch` over 27 class names, and the first session to write the
client would find it does not compile and would either move the factory into `game-client` (leaving
`game-core` unable to state its own schedule) or add a module dependency that the layering check
rejects. This records that the seam is deliberate and where each half belongs.

## Impact
`game-core` `system` (`SystemSlot`, `SystemProvider`, `SystemSetFactory`, `CoreSystemProvider`) and
`game-server-headless` (`ServerRuntime`). `game-client` will implement a second `SystemProvider` for
slots 1 and 22-26.
