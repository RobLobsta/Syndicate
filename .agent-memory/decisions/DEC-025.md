# DEC-025: slot 6 recomputes every tick, and the power budget is over live parts

**Date:** 2026-08-09
**Category:** decisions
**Related Docs:** docs/05_vehicle_part_system.md#D05-S5.6, docs/05_vehicle_part_system.md#D05-S5.7, docs/04_entity_component_model.md#D04-S4.5

**Status:** active

## Summary
`VehicleStatsSystem` aggregates every vehicle on every tick rather than gating on
`VehicleStats.dirty` or on a remembered `structuralVersion`, and its `powerBudget` sums the live
parts rather than the whole assembly.

## Details
**The trigger.** D05-S5.6 says the recompute runs "when `VehicleStats.dirty` or `structuralVersion`
changed". Comparing against a remembered version needs cross-tick state in a system field, which
D04-R3 prohibits — the same wall `MassPropertySystem` hit and answered by comparing its computed
result against the stored one (DEC-016). Stats have no equivalent: the aggregate *is* the stored
value, so "compute and compare" is the full recompute anyway.

That leaves the flag alone, and the flag is set by other systems. Nothing sets it when a part's
health changes, because `DamageSystem` (12) does not exist; when it does, a missed `dirty = true`
would be a vehicle driving on the degradation it had before the hit — a bug that presents several
seconds later as bad handling. Since aggregation is pure (D05-R27), recomputing when nothing changed
costs work and changes nothing, while skipping when something did is wrong. The cheaper failure is
chosen. `dirty` is still cleared, because D04-S4.3.2 has replication read it.

Cost is bounded and small: parts per vehicle ≤ 64 (`MAX_PARTS_PER_VEHICLE`) times 14 stats, so a
twelve-vehicle server is under 11 000 float operations per tick.

**The budget.** D05-S5.7's `computePowerBudget` takes an *assembly*, which is the build-time reading
AC-D05-18 checks and which `asset-pipeline` will use. At runtime the argument in D05-S5.6 phase 4 is
a *vehicle*, and R28 requires destroyed and detached parts to contribute exactly zero, so the sum is
over live parts. The two agree for an undamaged vehicle, which is the only case the balance rule
cares about.

## Rationale / Context
A future session profiling the tick will find slot 6 doing work it appears not to need and will be
tempted to gate it on `dirty` — which is correct only if every writer of health and structure
remembers to set the flag. This records that the flag was considered and deliberately not trusted,
so the change is made with the failure mode in view rather than as an obvious optimisation.

## Impact
`game-core` `system` (`VehicleStatsSystem`). Affects D05-S5.6 and D05-S5.7. If the tick budget of
D12-S5.5 ever puts slot 6 under pressure, the fix is a dirty flag written by every health and
structure writer plus a check that it is, not a version remembered inside the system.
