# DEC-069: the ground is a height field derived from a seed, not a mesh and not replicated

**Date:** 2026-08-14
**Category:** decisions
**Related Docs:** docs/16_procedural_arena_generation.md#D16-S5.2, docs/16_procedural_arena_generation.md#D16-S5.12, docs/16_procedural_arena_generation.md#D16-S5.8

**Status:** active

## Summary
An arena's ground is a regular height field generated at load from `(arenaId, terrainSeed)`, given
to Bullet as a `btHeightfieldTerrainShape`, and **derived independently by every peer** rather than
sent over the wire. The two rejected alternatives are a loaded triangle-mesh arena and a replicated
heightmap.

## Details
Three properties made the height field the only representation that satisfies everything at once:

- **The ray-cast wheel is built entirely on ray tests, and Bullet's convex ray test degrades with
  shape size** (DISC-017). That is why the floor is an infinite plane rather than a box, and why a
  mesh arena of large convex pieces would reintroduce a defect already paid for once. A height field
  is ray-tested per triangle, analytically, at any extent.
- **A query is arithmetic, not a search.** `heightAt`, `slopeDegAt` and `surfaceAt` are index
  computations on a regular grid, so wheel physics, bot navigation, spawn validation and structure
  placement can all ask about the ground every tick. On a triangle mesh each is a raycast.
- **It is generated, so it is free on the wire.** A 601² field is 1.4 MB; the seed is 8 bytes.

D16-R61 states the four rules that buy the determinism the last point depends on: integer hashing for
all lattice randomness (never `java.util.Random`), `StrictMath` for everything transcendental, a
fixed accumulation order, and no order-dependent parallelism. Same class of requirement as G3's
sorted iteration, and it fails the same way — invisibly, on one machine, as a desync.

## Rationale / Context
The failure this prevents: a mesh arena is the obvious design, and would be chosen by default because
`assets.collision` already exists in the arena schema (D08-S4.7) and DEV-014 records the mesh path as
merely "left for the session that has an arena mesh to load". A session taking that at face value
builds a concave triangle-mesh arena, watches the suspension jitter on it, and rediscovers DISC-017
from the other end.

The second failure is subtler: replicating the terrain. A heightmap is state, and state on the wire
acquires a delta encoder, a baseline and an ordering. Derived, it has no wire representation at all,
so it cannot desynchronise except through an impure generator — one testable property (D16-R62)
instead of a protocol.

## Impact
- Retires the standing DISC-017 risk for the ground specifically: the trap was "the moment an arena
  is built out of large boxes", and the ground is no longer a convex shape at all.
- Makes runtime terrain deformation a non-goal rather than a missing feature (D16-S2.2): craters
  would make the field mutable, which is what would make it replicated.
- Adds one hard native-ownership rule: Bullet does **not** copy the height data, so the direct
  buffer must be owned by `ShapeCache` for the shape's whole lifetime (D16-R47, G19).
