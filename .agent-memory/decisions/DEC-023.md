# DEC-023: a progress entry tracks one subsystem, and supersession never crosses subsystems

**Date:** 2026-08-09
**Category:** decisions
**Related Docs:** docs/13_persistent_memory_system.md#D13-S4.1, docs/13_persistent_memory_system.md#D13-S5.6, docs/13_persistent_memory_system.md#D13-S5.3

**Status:** active

## Summary
`progress/` holds one active entry per subsystem — simulation, destruction toolchain, content and
runtime shells — and a new entry supersedes only the entry for the same subsystem. PROG-001 to
PROG-006 formed a single global chain instead, which had already hidden a working subsystem behind a
superseded entry.

## Details
D13-S4.1 says a progress entry records "current implementation state per subsystem" and CLAUDE.md
§4 says "one entry = one subsystem's progress". The chain built up to this session did not work that
way: each new entry superseded the previous one whatever it was about, so `progress/` always held
exactly one active entry describing whatever the last session had touched.

**What that cost.** PROG-002 recorded that the Blender destruction tool and the verification harness
work end to end — five fixtures fracturing, mass conservation holding, captures rendering. PROG-003
superseded it while being entirely about `PhysicsSystem`, and PROG-004/005/006 continued down the
`game-core` line. By this session the only active progress entry was PROG-006, whose table says
`asset-pipeline: not_started` and says nothing about the toolchain at all. A session following
CLAUDE.md §4's read protocol — "start of every session: `INDEX.md`, then every active `progress/`
entry" — would have concluded the destruction pipeline did not exist.

**The rule.** Three subsystems, three active entries, each superseded only by its own successor:

| Subsystem | Active entry | Covers |
|---|---|---|
| Simulation | PROG-007 | `game-core`: ECS, physics, vehicle, damage, and the D04-S4.4 system catalogue |
| Destruction toolchain | PROG-008 | `blender-tool` and `test-environment` |
| Content and runtime shells | PROG-009 | `assets/`, `schemas/`, `asset-pipeline`, `game-client`, `game-server-headless` |

A fourth is added when a subsystem genuinely starts (networking and AI are inside PROG-007's
catalogue table until they are large enough to need their own).

The superseded entries stay exactly as they are — D13-S5.6 makes them a record, not a mistake to
tidy up. PROG-008 restates the toolchain's state from PROG-002 as of today rather than un-superseding
it.

## Rationale / Context
Without this, the chain continues and the next subsystem to go quiet for a few sessions vanishes the
same way the toolchain did — and the failure is silent, because an agent reading only active entries
has no way to notice that something is missing from a set it has never seen complete.

## Impact
`.agent-memory/progress/`. Affects how D13-S5.6's supersession is applied and what CLAUDE.md §4's
read protocol returns at the start of a session.
