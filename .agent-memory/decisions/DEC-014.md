# DEC-014: An attached part's mass lives in a bodyless RigidBodyComponent

**Date:** 2026-08-08
**Category:** decisions
**Related Docs:** docs/04_entity_component_model.md#D04-S4.3.1, docs/06_physics_simulation.md#D06-S5.7, docs/05_vehicle_part_system.md#D05-S4.4
**Status:** active

## Summary
A part that is attached to a vehicle carries a `RigidBodyComponent` whose `body` is null and whose `massKg` and `centerOfMassLocal` are its authoritative mass properties. `MassPropertySystem` sums those fields; nothing else in the component catalogue holds a part's mass at runtime.

## Details
D06-S5.7 sums `part.massKg` and `part.type.comLocal` over a vehicle's live parts. Neither exists as written:

- D05-S4.4 gives a part *type* a `massKg`, but the catalogue of D04-S4.3 has no component carrying it onto a part instance. `PartStatsComponent` holds a `StatBlock`, and D05-S4.5 deliberately excludes mass from the stat list.
- `part.type.comLocal` has no home at all — the fracture manifest records a `comLocal` (D09-S4.4), but no runtime component does.

The catalogue is closed: AC-D04-1 requires every component to exist "with exactly the listed fields", so adding a field or a component to carry these would be a spec deviation. `RigidBodyComponent` already declares both fields — `massKg` ("0 = static") and `centerOfMassLocal` ("Metres, in body-local space. Derived; updated per G10") — and nothing says a part may not have one without a body.

So an attached part is created with:

```
RigidBodyComponent { body = null, motionState = null,
                     shapeKey = (partTypeId, PART_HULL),
                     massKg = the part type's mass,
                     centerOfMassLocal = the part-local centre of mass,
                     layer = VEHICLE }
```

`body` becomes non-null only when the part detaches and becomes a debris body. That is consistent with DEC-004 — a vehicle is one body with a compound shape, and a part is geometry inside it, not a body — and it makes `shapeKey` meaningful for an attached part too, which is what `VehicleCompound` needs to look its hull up.

## Rationale / Context
Without this, the next session writing `SpawnSystem` or `DetachSystem` has to answer the same question from scratch, and the plausible-looking alternative — adding `massKg` to `PartStatsComponent` — silently breaks AC-D04-1 and makes every existing `MassPropertySystem` read wrong. It also explains a shape that looks odd on inspection: an entity with a `RigidBodyComponent` and no body is not a half-initialised entity, it is an attached part.

## Impact
`game-core` `component`, `system` (`MassPropertySystem`, `FractureSystem`), `vehicle` (`PartDetachment`). Constrains the future `SpawnSystem` (slot 5) and assembly loader: they must populate these two fields when they create a part entity.
