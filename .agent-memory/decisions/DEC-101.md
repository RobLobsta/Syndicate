# DEC-101: the debug console acts through the simulation's own entry points

**Date:** 2026-08-18
**Category:** decisions
**Related Docs:** docs/00_master_index.md#D00-S5.2, docs/03_runtime_modes.md#D03-S5.3, docs/04_entity_component_model.md#D04-S4.4

**Status:** active

## Summary
The live testing console may change the simulation — that is what it is for — but only by issuing
the same requests a player, a weapon or the arena pass issues. It never writes a component another
system owns and never alters the schedule.

## Details

**Where each control goes:**

| Control | Entry point | Why not the direct route |
|---|---|---|
| slow / pause / step | `ClientLoop` time scale | Scales the *real seconds admitted*, never `TICK_DT` (G2). A half-speed match runs the same fixed steps at half the rate, so results are bit-identical to full speed — which is what makes slow motion usable for diagnosis |
| spawn a vehicle | `SpawnQueue.request` | Slot 5 is where a spawn may happen. Building one mid-frame adds bodies to a Bullet world part-way through its step |
| place a structure | `StructureFactory.spawnStructure` | The same call `ArenaFactory`'s placement pass makes |
| damage | `DamageEvent` on the bus | The same event a projectile impact raises, through slot 12's own pipeline |
| freeze the AI | neutral `PlayerInputComponent` each frame | Not by unregistering `BotDecisionSystem`: the schedule is fixed (D04-S4.4), and a console that could remove a system from it could produce a world no build can otherwise reach |

**G6 and this class.** The invariant says cosmetic state must never feed back into gameplay, and the
console plainly affects gameplay. It is an exception with a stated boundary rather than a violation:
the console is a development affordance issuing sanctioned requests, and it is inert until opened.

**`--console` is a launch flag** taking a timeline (`open | f=20 spawn-structure | f=45 hit`),
following the precedent `--script` and `--night` set. A capture has no keyboard, so without it the
console is the one part of the client nothing can photograph — and it is the tool that produces
evidence about everything else. Frame-keyed (`f=`) as well as time-keyed (`t=`), because a headless
run renders at 2-5 fps and the first frame's delta swallows the whole asset load.

## Rationale / Context
Every number in this project is compiled in, and ROADMAP step 2 names the console as the thing that
has to exist before a tuning pass is possible. The risk in building one is that it grows a private
route into the world and stops being evidence about the game; the table above is the rule that
prevents it.

## Impact
- One defect found by building it: `EventBus.emit` queues for *listeners*, while `DamageSystem`
  drains the **same-tick** queue. A console hit emitted the ordinary way fired, logged and never
  touched its target.
- `ClientRuntime` now exposes `physics()`, `shapes()`, `assets()` and `spawnQueue()`.
