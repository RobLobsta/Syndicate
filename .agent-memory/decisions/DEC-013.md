# DEC-013: test-environment does not depend on gdx-gltf; D02-S4.5 amended to match

**Date:** 2026-08-08
**Category:** decisions
**Related Docs:** docs/02_technical_architecture.md#D02-S4.5, docs/14_test_environment.md#D14-S5.13

**Status:** active

## Summary
`gdx-gltf` is removed from `test-environment`'s dependencies and moved to its "MUST NOT depend on" column in D02-S4.5. No source in the repository ever imported it — DEC-008 made it unused — and it was the one artifact keeping the module from building without JitPack.

## Details

D02-S4.5's module table listed `gdx-gltf` for `test-environment`. DEC-008 then decided the harness would read `.glb` with its own `GlbReader`, precisely because gdx-gltf builds libGDX `Mesh` objects — GPU buffers that need a GL context, which D14-S5.13 forbids the headless runner from creating. The dependency line survived the decision that made it pointless.

Two things follow, and the second is why this is a `MUST NOT` rather than a silent deletion:

1. **It cost a session.** gdx-gltf publishes to JitPack only (DEV-001), JitPack is blocked by this environment's egress policy, and Gradle resolves a module's whole compile classpath whether or not anything imports it. So one unused line made `test-environment` unbuildable here, which is what deferred the DEV-007 fix in the first place.
2. **A dependency that is present but unusable is an invitation.** The harness runs its physics checks headless in CI. A future session reaching for gdx-gltf to load a fixture would find it on the classpath, use it, and break G17 in the one module whose job is to catch that kind of thing.

`game-client` keeps gdx-gltf. It has a GL context by definition, and DEC-003 makes glTF morph targets the runtime mesh format — that is where the importer belongs.

D02-S4.5 was amended in the same commit as the build change (CLAUDE.md §3 rule 10), with a note under the table recording the reasoning so the next reader does not restore the row.

## Rationale / Context
Without the note in D02, the obvious reading of the amended table is "someone trimmed a dependency" and the obvious fix, the next time a harness feature wants a glTF loader, is to add it back. The reason it is absent is a headless-safety constraint, not tidiness.

## Impact
`test-environment/build.gradle.kts`, `docs/02_technical_architecture.md#D02-S4.5`. Unblocked the DEV-007 refit and makes `:test-environment:check` runnable in any environment that can reach Maven Central.
