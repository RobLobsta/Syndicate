# DEC-084: a loadout is an assembly the index resolves but does not list

**Date:** 2026-08-16
**Category:** decisions
**Related Docs:** docs/01_product_game_design.md#D01-S2.2, docs/17_weapon_system.md#D17-S4.5

**Status:** active

## Summary
The garage lets a player choose which weapon sits on each hardpoint (D01-NG1a). A chosen loadout is
realised as a **real `AssemblyDef`** with its own id, registered on the asset index in a second map
that `assemblyIds()` and `assemblies()` do not see. Everything downstream resolves a vehicle by id
and nothing downstream has to know a garage exists.

## Details
Three options were weighed.

1. **Thread an `AssemblyDef` through the ECS** so the spawn path takes an object rather than an id.
   Rejected: `PlayerIdentityComponent.selectedAssemblyId` is replicated, and a component that
   sometimes carries a whole assembly is a networking problem invented to avoid a map.
2. **Replace the shipped assembly in the index** under its own id. Rejected outright: bots draw
   their vehicles from the same index (D11-R12), so one player's loadout would arm every bot that
   happened to pick that car.
3. **A separate map, keyed by a `_fitted` id.** Chosen. `assembly(id)` falls back to it, so the
   preview, the spawn path and the match report all work unchanged; `assemblyIds()` and
   `assemblies()` return only the catalogue, so a bot cannot draw a configured vehicle and the
   garage cannot list one. The exclusion is structural rather than a predicate three call sites have
   to remember.

A loadout equal to what the vehicle ships with returns the shipped assembly **identically** — same
object, same id — so an untouched playthrough puts nothing on the second map and a match report says
`vehicle_stampede_01` rather than `vehicle_stampede_01_fitted`. The suffix is only present when it is
telling the truth about something.

The `expected` block is dropped rather than recomputed. It is the artist's assertion about the
vehicle they authored (D08-R10); carrying it forward asserts a mass that is no longer true, and
recomputing it turns a check into a tautology.

## Rationale / Context
The failure this avoids is subtle and would have been found in a match rather than in a test: bots
and the player share one index, and "register the customised vehicle" is the obvious implementation
of a garage. Nothing about it looks wrong until the scoreboard shows four bots driving the car you
just built.

## Impact
- `InMemoryAssetIndex` gained `putConfigured` and a private `configured` map; `assembly()` falls
  back to it, `assemblyIds()` and `assemblies()` do not.
- `WeaponLoadout.applyTo` is a pure function of an assembly and an index, so a headless server
  builds the same vehicle as the client (G17, G3).
- D01-NG1a, D08's A222 and D17-R16 were amended in the same commit.
