# DEC-010: CI runs the D12-S5.4 stages as steps in one job, not one job per stage

**Date:** 2026-08-08
**Category:** decisions
**Related Docs:** docs/12_testing_validation_ci.md#D12-S5.4, docs/02_technical_architecture.md#D02-S4.6

**Status:** active

## Summary
The workflow ran three jobs (stages 0, 1-2, 7) and triggered on both `push: ["**"]` and `pull_request`, so every commit on a branch with an open PR ran the whole pipeline twice: 6 jobs, 573 s of runner time, for one commit's worth of information. It is now a single job whose steps are the stages, triggered on `pull_request` plus `push` to `main` only.

## Details

**Measured waste**, from run 31256757764 (push) and 31256759355 (pull_request), same SHA, created 3 seconds apart:

| | jobs | runner time |
|---|---|---|
| push run | 3 | 280 s |
| pull_request run | 3 | 293 s |
| **per commit** | **6** | **573 s** |

Each of the six jobs did its own checkout, JDK install, and Gradle cache restore before doing any work.

**What D12-R11 actually requires.** It defines the stages as an ordered sequence of Gradle tasks, each gating what follows, and requires each to be reproducible locally. It says nothing about runners. Steps in one job preserve the ordering, the gating, and the per-stage attribution in the UI; what is lost is only the triple setup cost. There was never parallelism to gain, because the stages are strictly sequential gates.

**Trigger change.** `push` is limited to `main`; everything else is covered by its pull request. The tradeoff is explicit: **a branch with no open PR gets no CI.** That suits a workflow where work reaches `main` through a PR, and it is the single biggest saving available.

**Stage 7 (package) is dropped for now**, at the user's direction — distribution packaging is not what current work is verifying. It is also the one stage D12-S5.4 does not mark as a gate. `:game-client:distZip` and the D02-E12 art-source assertion return with it.

**Also:** test reports upload only `if: failure()`. A green run's reports are never read, and uploading them cost storage and time on every build.

## Rationale / Context
GitHub Actions minutes are a limited resource on this account, and the duplication was invisible in the UI — two green check marks look like thorough CI rather than the same work done twice. Recorded so the next person to add a trigger or split a job knows the cost and the reasoning, rather than restoring `push: ["**"]` because it looks more complete.

## Impact
`.github/workflows/ci.yml`. D12-S5.4's stage list is unchanged; only its mapping onto runners is. Stages 3-6 remain unimplemented and stage 7 is now deferred rather than implemented.
