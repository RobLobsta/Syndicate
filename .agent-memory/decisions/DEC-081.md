# DEC-081: size class gates bulk, mass gates load, and they are separate numbers

**Date:** 2026-08-16
**Category:** decisions
**Related Docs:** docs/17_weapon_system.md#D17-S4.3, docs/05_vehicle_part_system.md#D05-S4.3, docs/08_asset_pipeline.md#D08-S5.4

**Status:** active

## Summary
`SizeClass` — `LIGHT`, `MEDIUM`, `HEAVY` — is carried by both a slot definition and a part type, and
**a slot accepts its own class and every class below it**. It sits alongside the two gates that
already existed rather than replacing either: `SlotType` decides *what kind* of thing attaches, size
class decides *how bulky*, and `maxMassKg` decides *how heavy*. A violation is `A316`.

## Details
Both fields default to `MEDIUM` when absent (D17-R8), so every part and slot authored before this
change behaves exactly as it did. `SizeClass.parse` returns `MEDIUM` for null or blank and **null**
for an unrecognised name, which is what lets the loader tell "the field is absent" from "the field
says `HEAVEY`" and report the second as `A221`.

The five hardpoints every prepared vehicle offers take their class from **where they are**, which is
the only thing about them the geometry decides: `turret_main` is `HEAVY` because the roof centreline
is the one place a big gun sits without fouling the wheels; the bonnet and tail are `MEDIUM`; the
flanks are `LIGHT` because anything bulky out there is wider than the car.

## Rationale / Context
The user asked for a mechanism, and three were on the table: size classes, a per-slot family
allow-list, and mass caps alone. Mass alone is the tempting one and it is wrong: a small dense object
passes a bulk test and fails a load test, and collapsing the two into one number makes "does this fit
here" unanswerable. A family allow-list is the most explicit and needs per-vehicle authoring for
every new weapon family, which is exactly the per-model tuning D15-R7 exists to avoid.

## Impact
- `A316` fires on eight hub slots the moment the classes were added, because a hub slot rated
  `LIGHT` was holding a hub part defaulted to `MEDIUM`. Fixed by classing hub parts `LIGHT` in
  `syndicate_prepare`, which is the honest answer — a brake hub is light.
- `SlotDefinition.accepts(category, massKg, sizeClass)` is the one statement of the rule; the
  validator still tests the three separately so it can say *which* gate failed.
