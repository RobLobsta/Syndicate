# DEC-003: glTF 2.0 (.glb) is the runtime mesh format, chosen for morph target support

**Date:** 2026-08-07
**Category:** decisions
**Related Docs:** docs/08_asset_pipeline.md#D08-S4.5, docs/09_blender_destruction_tool.md#D09-S5.6
**Status:** active

## Summary
Processed meshes ship as glTF 2.0 binary (`.glb`), imported with gdx-gltf, because it is the only well-supported format that carries morph targets as a first-class feature.

## Details
Damage deformation is implemented with Blender shape keys exported as glTF morph targets (D07-S5.5). That single requirement eliminates OBJ (no morphs, no hierarchy, no custom properties) and makes libGDX's own `.g3db` awkward, since it is produced from FBX via `fbx-conv` and morph support is not a first-class path. FBX itself is proprietary and its Blender exporter is lossy in practice.

glTF also carries the node hierarchy the shard nodes and slot empties need, and an `extras` object for custom properties, so no sidecar format is required.

Draco compression is explicitly disabled: it is lossy on morph deltas and would break the tool's determinism guarantee (G11).

## Rationale / Context
If a future session optimises startup by switching to a binary format, morph target fidelity is the thing that will silently degrade — and visual damage failing subtly is much harder to notice than it failing loudly.

## Impact
`asset-pipeline`, `game-core`'s `asset` package, the Blender tool's export stage, and the harness's mesh loading.
