# DEC-031: a part authors physics it cannot express as a stat in a handling block

**Date:** 2026-08-09
**Category:** decisions
**Related Docs:** docs/08_asset_pipeline.md#D08-S4.2, docs/06_physics_simulation.md#D06-S4.5, docs/05_vehicle_part_system.md#D05-S4.5

**Status:** active

## Summary
`HandlingBlock` carries the nine physical parameters D06-S4.5's reference chassis table names and
D05-S4.5's stat list cannot hold: drag, rolling resistance and downforce on a chassis; damping, roll
influence and suspension geometry on a wheel. It is authored as a `handling` object on the part, and
D08-R5 was amended in the same commit.

## Details
**Why not stats.** D05-S4.5's fourteen stats are all *contributions*: a force, a grip figure, a rate,
summed or averaged across the parts that declare them. Aerodynamic drag is not. Two chassis do not
have twice the drag coefficient of one, and a stat block's `add` term means precisely that they
would. The same holds for damping and roll influence, which describe one corner rather than a
vehicle-wide total.

**Why on the part.** D05-S5.6 phase 4 already says drag and rolling resistance come "from the chassis
part". Before this there was nowhere on a part to put them, which is why DEC-027 made them constants.
They are now authored, and DEC-027's values became the defaults.

**Defaults, not nulls.** Every field is optional and falls back to D06-S4.5's reference chassis, so a
part authoring only a drag coefficient keeps the reference suspension rather than getting zeros.
`HandlingBlock.REFERENCE` is where that table lives in code, and `VehicleFactory`,
`VehicleStatsSystem` and `VehicleControlSystem` take their constants from it — one table in the
blueprint, one in the code, after DEC-029 found three copies of it drifting.

**Downforce reaches slot 7 through the stats component.** `VehicleControlSystem` has no asset index
and should not grow one to read a single float, so slot 6 copies the chassis's downforce onto
`VehicleStatsComponent` while it is already looking the part type up.

## Rationale / Context
The next session wanting a per-vehicle physical property — brake bias, a centre-of-pressure offset, a
tyre temperature model — will reach for a new stat, because that is where every other authored number
lives. This records the test: a *contribution* is a stat, a *property* is handling. Getting it wrong
is not a compile error; it is a vehicle whose drag doubles when somebody bolts on a second engine.

## Impact
`game-core` `asset` (`HandlingBlock`, `PartType`, `AssetLoader`), `vehicle` (`VehicleFactory`) and
`system` (`VehicleStatsSystem`, `VehicleControlSystem`). Amends D08-R5's schema table and
D04-S4.3.2's `VehicleStatsComponent` row.
