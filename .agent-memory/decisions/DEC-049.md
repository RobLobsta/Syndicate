# DEC-049: a PRESENT system is handed frame time, and reads alpha off the world

**Date:** 2026-08-11
**Category:** decisions
**Related Docs:** docs/03_runtime_modes.md#D03-S5.3, docs/04_entity_component_model.md#D04-S4.5, docs/07_damage_destruction_model.md#D07-S5.5

**Status:** active

## Summary
`World.present(alpha, frameDtSeconds)` passes the real frame delta as a PRESENT system's `dtSeconds` and exposes the render interpolation factor separately through `World.renderAlpha()`. The single-argument `present(alpha)`, which passed alpha as the dt, is gone.

## Details
D03-S5.3 writes `runPresentSystems(world, alpha)` and D07-S5.5 writes `DamageVisualSystem.update(world, dt)`. Both are needed, and they are different numbers:

- **alpha** is where in the current tick this frame landed, in `[0,1)`. Slot 22 uses it to place a body between two simulated positions.
- **frame dt** is how much real time the frame covers. Slot 23 eases morph weights at `MORPH_LERP_RATE` per *second*, slot 24 integrates particles, and slot 26 has nothing to do with either.

The old signature made them the same argument, so the crumple speed of a damaged panel was decided by where in the tick the frame happened to fall — at alpha near zero, a mesh eased at almost no rate; at alpha near one, sixty times faster. Both are wrong and neither is visible in a screenshot.

`EntitySystem.update(World, float dtSeconds, long tick)` is unchanged. `dtSeconds` already means "the time this call covers", which for a per-tick system is `TICK_DT` and for a per-frame system is the frame delta; that reading is consistent, and it left alpha with nowhere to go but the world. `renderAlpha()` is set for the duration of the `present` call and documented as readable by PRESENT systems only (D03-R11).

## Rationale / Context
Without this, a future session reading `update(world, alpha, tick)` in a client system has no way to tell that the second argument is not the elapsed time every other system receives, and will write a per-second rate against it. The bug produces a plausible-looking result at every frame rate and a wrong one at all of them.

## Impact
- `game-core` `World`: new `renderAlpha()` field and accessor; `present` takes two arguments.
- Every `game-client` PRESENT system (slots 22–26).
- `ScheduleTest` asserts both halves.
