# DEC-092: A309 asks whether a vehicle can move, and a rotor answers too

**Date:** 2026-08-17
**Category:** decisions
**Related Docs:** docs/08_asset_pipeline.md#D08-S5.4, docs/05_vehicle_part_system.md#D05-S5.1

**Status:** active

## Summary
`A309` — "fewer than 3 wheels" — becomes "fewer than 3 wheels **and no rotor**". Both independent
implementations change together: `AssemblyValidator.checkWheelCount` in `game-core`, which enforces
it at load, and `AssetIndexBuilder` in `asset-pipeline`, which enforces it at the gate (DEC-041).

## Details
The Kestrel is a well-formed vehicle with zero wheels, and A309 rejected it as an error — the only
error in an otherwise clean strict run of the asset gate.

The rule's *intent* is that a vehicle can move under its own power: three wheels is the fewest a
ray-cast vehicle can stand and drive on, and an assembly with two is an authoring mistake that
produces something that cannot be played. That intent is unchanged. What changed is that there is now
a second way to satisfy it, and the check tests for the intent rather than for its only previous
implementation.

`countCategory(ROTOR) > 0` rather than "has a MAIN rotor": the gate's job is to catch an assembly
that is obviously broken, and an aircraft with only a tail rotor is caught by the flight model doing
nothing rather than by a validation rule pretending to know more than it does. `isRotorcraft` — the
runtime flag that decides which control operation runs — *does* require a main rotor (DEC-090), and
the two are deliberately different questions.

## Rationale / Context
The concrete future failure this stops is the shape of the fix rather than the fix: the tempting
answer was to give the Kestrel three token `WHEEL` parts for its skids so the existing rule passed.
That produces an aircraft with three ray-cast wheels reporting ground contact, which feeds
`isAirborne`, which decides which speed clamp applies — so the "harmless" workaround would have
silently changed the physics of every helicopter in the game to keep a validation rule honest.

Both copies of the rule were changed in the same commit, and the pipeline's carries a comment saying
so, because DEC-041's whole premise is two independent implementations of one set of rule codes —
which is only a strength while they agree.

## Impact
`game-core/AssemblyValidator`, `asset-pipeline/AssetIndexBuilder`. D08-S5.4's A309 row is amended.
The strict asset run goes from 1 error to 0.
