# DEC-051: the client attaches its own cosmetic components; core factories never do

**Date:** 2026-08-11
**Category:** decisions
**Related Docs:** docs/04_entity_component_model.md#D04-S4.2, docs/03_runtime_modes.md#D03-S5.5, docs/07_damage_destruction_model.md#D07-S5.5

**Status:** active

## Summary
`RenderTransformComponent`, `RenderModelComponent` and `DamageVisualComponent` are attached by the client systems that own them — slots 22, 26 and 23 respectively — each through a family that excludes the component it is about to add. `VehicleFactory` and `DebrisFactory` attach none of them.

## Details
D04-S4.2's `PART` archetype lists `DamageVisual`, and something has to create it. The obvious home is `VehicleFactory`, which builds every other component a part carries. That is wrong for one reason: the same factory runs on a dedicated server, which D03-R13 says never loads morph geometry and D02-R9 forbids from importing anything graphical. A factory that built render state would carry G17's violation in the one code path every mode shares.

So each client system opens two families: `all(X).exclude(TheComponent)` to attach, and `all(X, TheComponent)` to work on. Attaching during iteration is legal (D04-R12) and takes effect at the next family query, which is the next frame — so a part is drawn from the frame after it appears, and slot 23 has its weights correct before slot 26 ever has a mesh to write them to.

The same rule places `ParticleRefComponent`: slot 24 creates `EFFECT` entities itself, and no core factory knows the archetype exists.

## Rationale / Context
The pull toward "the factory builds the whole archetype" is strong and will recur every time a component is added to `PART`. The counter-argument is not style; it is that `game-core` has a mechanical check (`checkHeadlessSafety`) which would reject the import, and a session that works around the check rather than moving the attachment has broken the dedicated server.

## Impact
- `game-client` slots 22, 23, 24, 26.
- `game-core` `VehicleFactory`, `DebrisFactory`: unchanged, deliberately.
- The client-only components take component-type indices after `ComponentCatalogue`'s 36, as `RenderModelComponent` already did.
