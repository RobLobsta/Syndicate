# DEC-061: vehicle control becomes a shared operation so reconciliation can replay it

**Date:** 2026-08-13
**Category:** decisions
**Related Docs:** docs/06_physics_simulation.md#D06-S5.5, docs/10_networking_multiplayer.md#D10-S5.5, docs/04_entity_component_model.md#D04-S4.5

**Status:** active

## Summary
The body of `VehicleControlSystem` (slot 7) moves to `dev.syndicate.core.vehicle.VehicleControl`.
The system keeps the slot, the family and its public constants; `ReconciliationSystem` (20) holds its
own instance.

## Details
D10-S5.5's rewind-and-replay re-applies every unacknowledged input on top of the authority's state.
Replaying through anything but the arithmetic the authority used turns a transient prediction error
into a permanent offset — every replayed tick would add the same difference again — so slot 20 needs
slot 7's code, and D04-R13 forbids a system calling a system.

This is the third instance of the same pattern: `PartDetachment` (DEC-016) and `DamageApplication`
(DEC-038) were extracted for exactly this reason. The rule is now clear enough to state: **when two
schedule slots need the same arithmetic, the arithmetic is an operation and the slots are
schedules.**

## Rationale / Context
The alternative — slot 20 constructing its own `VehicleControlSystem` and calling `update` — is a
system-to-system call wearing a disguise, and it would also drive every vehicle in the world rather
than the one being replayed.

## Impact
- New `VehicleControl`; `VehicleControlSystem` is 90 lines and delegates.
- Its constants remain on the system as aliases, so existing tests and `test-environment` compile
  unchanged.
