# DEC-019: the chassis is a field on the assembly record, not a row in its parts list

**Date:** 2026-08-09
**Category:** decisions
**Related Docs:** docs/08_asset_pipeline.md#D08-S4.4, docs/05_vehicle_part_system.md#D05-S5.1, docs/00_master_index.md#D00-S5.1

**Status:** active

## Summary
`AssemblyDef` carries `chassisPartTypeId` as its own field and lists only the attached parts in
`parts`, following D08-S4.4's file format rather than D05-S5.1's validation pseudocode, which reads
the root out of `parts` by looking for a null `parentSlotPath`.

## Details
The two documents describe the same data differently:

- **D08-S4.4** (the schema) has a top-level `"chassis": "chassis_medium_01"` and a `parts[]` array
  in which every entry has a `parentSlotPath`. There is no row for the chassis.
- **D05-S5.1** (`validateAssembly`) begins `roots = assembly.parts.filter(p -> p.parentSlotPath ==
  null)` and reports an error unless exactly one is found.

D00-S5.1 resolves this by owning document: the file format belongs to D08 (D00-S4.2's table), so the
JSON shape wins and the runtime record mirrors it.

The consequence is that **A301 splits in half**. "Exactly one root" stops being a check at all — a
record with one non-null field cannot have zero or two — and what remains is "the named type is of
category `chassis`", which `AssemblyValidator` still reports as A301. T-D05-1 ("validate an assembly
with two chassis → rejected with 'exactly one root'") is therefore satisfied structurally rather than
by a diagnostic: a second chassis in `parts` fails A305 instead, because no slot type accepts
`CHASSIS`.

`AssemblyLayout` mirrors the same asymmetry: the chassis is index 0, at slot path `root`, with a null
`parentSlotPath` and a null `SlotDefinition` — it occupies no slot because nothing above it offers
one. `PlacedPart.isChassis()` is that null check, named.

## Rationale / Context
Without this, the next session reading D05-S5.1 finds a validator that never emits "assembly must
have exactly one root", concludes the rule was skipped, and either adds a check that cannot fire or
restructures the record to make it able to. The blueprints disagree; this records which one the code
follows and what happened to the rule that lost.

## Impact
`game-core` `asset` (`AssemblyDef`, `AssemblyLayout`, `AssemblyValidator`) and every caller of the
spawn path. Affects D05-S5.1's A301 and T-D05-1; D08-S4.4 is unchanged and remains authoritative.
