# DEC-008: The harness parses GLB itself rather than importing it through gdx-gltf

**Date:** 2026-08-08
**Category:** decisions
**Related Docs:** docs/14_test_environment.md#D14-S5.13, docs/02_technical_architecture.md#D02-S4.5

**Status:** active

## Summary
`test-environment` reads vertex positions and indices out of `.glb` with its own reader (`GlbReader`, ~200 lines) instead of loading the file through gdx-gltf. The decisive reason is that gdx-gltf builds libGDX `Mesh` objects, which are GPU buffers requiring a GL context — and D14-S5.13 requires the headless runner to create none.

## Details

**Options considered:**

| Option | Verdict | Reasoning |
|---|---|---|
| **Direct GLB reader** | **CHOSEN** | No GL context, so the asset and physics checks — the ones CI actually runs — work headless (G17). The harness reads only what it measures: node names, `POSITION`, indices. |
| gdx-gltf `SceneAsset` | Rejected | Needs a GL context to upload meshes. Would put the harness's most valuable half behind a display server, and D14-S5.13 forbids it outright. |
| gdx-gltf in visual mode, reader in headless | Rejected | Two loaders means the rendered frame and the simulated bodies come from different geometry. A capture is meant to be evidence about the simulation; that only holds if both are fed from the same parse. |

**Consequence for rendering:** the visual mode builds its own `Mesh` objects from the same `MeshData` the physics uses, with per-face normals, through a hand-written shader. Materials and textures are not read, which is acceptable — the harness colours shards by index (the `shardcolor` overlay of D14-S5.11) rather than by material, because telling shards apart is the point.

## Rationale / Context
`test-environment/build.gradle.kts` still declares a gdx-gltf dependency (D02-S4.5 lists it), and the obvious future edit is "use the library that is already on the classpath". That change would silently make the CI checks require a display.

## Impact
`test-environment/.../asset/GlbReader.java`, `MeshData.java`, `render/SceneRenderer.java`. Morph targets are not read by the harness; ASSET-007 checks the manifest's declared names, and the tool's TV-006 checks they survived export (D09-R15).
