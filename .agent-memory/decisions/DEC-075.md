# DEC-075: a vehicle owns its parts; the shared library is what is modular

**Date:** 2026-08-15
**Category:** decisions
**Related Docs:** docs/08_asset_pipeline.md#D08-S4.6, docs/15_vehicle_preparation_pipeline.md#D15-S5.10, docs/05_vehicle_part_system.md#D05-S4.3

**Status:** active

## Summary
A part now lives in one of two places, and which one says what it is for.
`assets/vehicles/<vehicleTypeId>/parts/<partTypeId>/` holds a **vehicle-owned** part — a chassis, a
door, a wheel — and only that vehicle's assembly may reference it (A315). `assets/parts/` becomes
the **shared library**: weapons, utility modules, universal accessories, fitted to anything with the
right slot. The flat `assets/parts/` that held both is gone.

## Details
`AssetPaths` in `shared-models` is the one answer to "where does this part live", used by the runtime
loader, the asset gate, the client's model cache and the verification harness — four consumers, none
of which may depend on another. It walks shared first, then each vehicle in id order (G3), and
derives ownership from the path rather than from the file, because the directory *is* the ownership
statement: a `part.json` never names a vehicle.

The gate gains two rules. A106 already reported a duplicate id and now names both paths; A315 is new
and refuses an assembly that references a part owned by a different vehicle. Both were unenforceable
before, because one flat directory cannot distinguish a shared part from somebody else's door.

`assets/vehicles/<id>/parts/manifest.json` sits with the parts it describes: per part, what it is,
what it weighs, what it costs, how it fails, how many triangles it took; plus the vehicle's totals
and its hardpoints. Nothing loads it and every number in it is copied from a `part.json` written in
the same run — it exists for the question a directory listing cannot answer.

## Rationale / Context
Two failures the flat layout could neither prevent nor detect. A door cut from one car's art is the
wrong size, in the wrong place, and carries a mass derived from a body it is not on — bolting it to
another vehicle produces a car that loads and is wrong. And two cars whose art both produced a
`panel_door_l_01` would have collided outright.

Weapons are the case that forces the split rather than merely rewarding it: a weapon *must* be
shareable, so "everything is shared" and "a vehicle's parts are its own" cannot both be expressed in
one directory.

## Impact
- 53 parts across two vehicles, none of them shared; `assets/parts/` ships a README and nothing else.
- `asset-index.json` carries `ownedBy` and a real path per part.
- The five-part chassis-and-wheels content is retired (see PROG-034).
