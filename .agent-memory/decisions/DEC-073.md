# DEC-073: `ARMOR` names two different things, and the collision is left for the user

**Date:** 2026-08-14
**Category:** decisions
**Related Docs:** docs/05_vehicle_part_system.md#D05-S4.3, docs/15_vehicle_preparation_pipeline.md#D15-S4.1, docs/08_asset_pipeline.md#D08-S4.2

**Status:** active

## Summary
The word *armour* currently covers both "bolted-on protective plating a player chooses" (D01, D05)
and "any body panel — a door, a bonnet, a bumper" (DEC-063, the preparation pipeline). Both readings
are defensible, they are not the same concept, and the ambiguity is now load-bearing in the
taxonomy. This entry records the collision and the options; **the choice is the user's and has not
been made.**

## Details
`PartCategory.ARMOR` and `SlotType.ARMOR_PANEL` were specified for plating. DEC-063 then mapped the
preparation pipeline's `panel` label onto them, with a sound argument: a door covers a region,
absorbs hits meant for what is behind it, and can be shot off, which is what D05 means by armour.

The consequence is that a prepared car has twenty-odd "armour" parts that are its bodywork, and a
future build-your-own-loadout feature would have no separate word for the plating a player bolts on.
On a garage screen it already reads oddly: the Eclipse's `ARMOUR 18` is its chassis' rating, while
its doors are also, separately, armour.

Three ways out:

1. **Leave it.** One category, documented as "anything that covers and can be shot off". Cheapest,
   and it stays wrong the first time a player is offered a choice between a door and a plate.
2. **Split the category** into `PANEL` (bodywork the vehicle came with) and `ARMOR` (plating that is
   fitted). Costs a `PartCategory` member, a `SlotType` member, a row in D05-S4.3's acceptance table,
   a remap in the pipeline's label table, and a re-cut of any prepared content.
3. **Rename the existing one to `PANEL`** and reserve `ARMOR` for later. Cheaper than 2, and it
   admits today's truth without inventing a feature that does not exist.

A separate, smaller point: identifiers and JSON use US spelling (`armorValue`, `ARMOR_PANEL`) while
every comment and document uses British (`armour`). That is a consistent and common convention —
code in one, prose in the other — but it is written down nowhere, so it looks like drift.

## Rationale / Context
This is exactly the kind of ambiguity that is cheap now and expensive after content exists. Once
several vehicles have been prepared and shipped, changing what `ARMOR` means means re-cutting all of
them. Recording it rather than quietly picking one keeps the decision where it belongs.

## Impact
- No code changed. `ARMOR` still means both things.
- Option 3 is the recommendation: it is a rename plus a doc amendment, and it stops the word
  promising a feature the product does not have (D01-NG1).
- Whichever is chosen, D02-S4.7 should gain one line fixing the spelling convention explicitly.
