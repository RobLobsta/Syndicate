# DEV-002: Cell Fracture is unavailable; cells built by half-space clipping

**Date:** 2026-08-08
**Category:** spec_deviations
**Related Docs:** docs/09_blender_destruction_tool.md#D09-S5.2, docs/09_blender_destruction_tool.md#D09-S4.1

**Status:** active

## Summary
D09-S5.2 drives Blender's Cell Fracture add-on (`bpy.ops.object.add_fracture_cell_objects`), which wraps voro++. That add-on is not part of Blender 4.2's core distribution — it moved to the extensions platform — and is absent from both a stock install and the `bpy` PyPI module. Cells are constructed directly instead, by clipping a copy of the source mesh with the perpendicular-bisector half-spaces between sites.

## Details

**Deviates from:** D09-S5.2 step 2b (the `add_fracture_cell_objects` call), and D09-R1's `blender --background` invocation.

**What changed:**
1. `fracture.py` clips a bmesh copy of the source with `bmesh.ops.bisect_plane(clear_outer=True)` once per bisector, filling each cut with `triangle_fill`. A Voronoi cell *is* the set of points closer to its site than to any other, which is exactly the intersection of those half-spaces — so this is the same cell the add-on would produce, intersected with the source mesh in the same operation rather than as a separate boolean.
2. The tool runs under either `blender --background --factory-startup --python -m syndicate_fracture` (D09-R1) or `python3 -m syndicate_fracture` with the `bpy` PyPI module. `bpy` is Blender 4.2 built as a Python extension — the same codebase — and is the only host available in environments with no `blender` executable. `blender.py` supports both; `build.gradle.kts` prefers the executable when present.

**Everything D09-S5.2 requires that is unchanged:** sites come from the tool's own PCG32 and never from Blender's randomness; sites are sorted lexicographically before use and shards re-sorted by quantised centroid after (D09-R10); sub-minimum cells are merged into their nearest neighbour, never dropped (D09-R11); there is no recursion (D09-R9).

## Rationale / Context
Without this entry the next session finds an implementation that does not call the operator the spec names, assumes it was an oversight, and either re-adds a dependency on an add-on that cannot be installed or rewrites working, deterministic code.

## Impact
`blender-tool/syndicate_fracture/fracture.py`, `blender.py`, `build.gradle.kts`, and the D09-S5.2 pseudocode.

**Blueprint Disposition: DOC_SHOULD_CHANGE.** D09-S5.2 names a specific add-on that Blender no longer ships. The bisection construction is not a workaround — it is the definition of a Voronoi cell, needs no third-party library, and removes the add-on-state dependency D09-S5.2 itself warns about as a determinism risk (G11).
