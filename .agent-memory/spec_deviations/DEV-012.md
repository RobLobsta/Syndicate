# DEV-012: every body is added with DefaultFilter in its mask, beyond D06-S4.4's table

**Date:** 2026-08-09
**Category:** spec_deviations
**Related Docs:** docs/06_physics_simulation.md#D06-S4.4, docs/06_physics_simulation.md#D06-S5.5

**Status:** active

## Summary
`PhysicsWorld.addBody(body, layer)` passes `layer.mask() | 1` to Bullet rather than `layer.mask()`.
The extra bit is `btBroadphaseProxy::DefaultFilter`, without which a ray-cast wheel finds no ground
on any surface (DISC-011).

## Details
**Deviates from:** `docs/06_physics_simulation.md#D06-S4.4` (D06-R9), whose `MASKS` block reads
`STATIC = VEHICLE | PROJECTILE | DEBRIS | PROP`. The other six layers already contain the bit,
because it is numerically `STATIC.bit` and they all collide with static geometry; `STATIC`'s own mask
is the one this changes.

The reason is Bullet's, not ours: `btDefaultVehicleRaycaster` constructs its ray callback internally
on `DefaultFilter` and cannot be told otherwise, and Bullet's filter test requires both directions to
pass. DISC-011 has the mechanism and the symptom.

**Nothing about pair collision changes.** The only pairing the extra bit newly admits is `STATIC`
against `STATIC`, and `btCollisionDispatcher::needsCollision` rejects a pair of non-dynamic bodies
before it reaches a manifold — two bodies with no mass have nothing to solve. Every relation D06-R9 and D06-R10 state is unchanged, and `CollisionLayer.collidesWith` — which answers questions about the table
rather than about Bullet — is untouched.

## Rationale / Context
A session comparing `CollisionLayer.mask()` against D06-S4.4 will find them equal and conclude the
implementation is faithful; the `| 1` is one token in `PhysicsWorld` and reads like a typo. Removing
it breaks every vehicle in the game in a way that looks like a suspension tuning problem.

## Impact
`game-core` `physics` (`PhysicsWorld`). Affects D06-S4.4 and, through it, D06-S5.5.

**Blueprint Disposition: DOC_SHOULD_CHANGE.** D06-S4.4 describes pair collision and is silent on how
Bullet's internal ray tests are filtered, which is a real hole rather than a wrong value. A note
stating the `DefaultFilter` requirement was added to D06-S4.4 in the same commit; the numbered rules
R9-R11 are unchanged, because none of them is wrong.
