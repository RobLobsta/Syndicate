# DEV-005: cells on curved sources are not true Voronoi cells

**Date:** 2026-08-08
**Category:** spec_deviations
**Related Docs:** docs/09_blender_destruction_tool.md#D09-S5.2, docs/14_test_environment.md#D14-S7.1

**Status:** active

## Summary
The bisect-and-fill cell construction of DEV-002 produces exact Voronoi cells on a planar-faced source and materially wrong ones on a curved source. On `test_sphere_r0.5`, 178 of 2400 sampled interior points are closer to a foreign site than to their own cell's — median depth 5.5% of the part's extent, worst 18.4%. These are mis-assignments, not boundary noise.

## Details

**Deviates from:** D09-S5.2, which specifies a Voronoi decomposition; (D09-R10) assumes the cells it orders are Voronoi cells.

**What is still true**, which is why nothing else catches it:

| Property | cube | sphere |
|---|---|---|
| Cells bounded | yes | yes |
| Cells tile the source (volume sums to source ± 0.5%) | yes | yes |
| Interior points nearest their own site | 2400/2400 | 2222/2400 |

The shards remain a valid decomposition of the solid — they tile, they conserve mass to 0.006%, they build valid hulls, and all 31 harness checks pass. What is wrong is the *shape* of the partition: shard boundaries on a curved part are not the perpendicular bisectors they should be.

**Cause:** `triangle_fill` re-triangulates each planar cut, and on a curved source a later plane cuts through an earlier fill, so the accumulated boundary drifts from the true bisector. The same fragility, more severely, is what makes DEV-004's hollow box fail outright.

**Attempted and rejected:** replacing bisect-and-fill with a convex cell polyhedron intersected against the source via Blender's Exact boolean solver — the mechanism the Cell Fracture add-on uses internally. The cell polyhedra were verified correct (they tile their seed box to 1.0000), but the boolean stage was not reliable at these operand ratios: with a large seed box the solver failed on individual cells and silently returned the *unmodified* source (the plate summed to 1.94x its mass); with a tight one, near-coincident faces produced results larger than either operand. A deterministic ladder of seed-box sizes with a volume guard still lost 7–18% of volume across four fixtures that had been passing. The attempt was reverted; see the measurements in this entry rather than re-running it.

## Rationale / Context
Recorded because the defect is invisible to every existing check and to visual inspection: a sphere fractured this way looks entirely convincing, conserves mass, and passes 31/31. Only the nearest-site property distinguishes it, which is why that property is now a test (`tests/blender/test_voronoi_properties.py`) with the sphere case as a strict xfail — so fixing it announces itself.

## Impact
`blender-tool/syndicate_fracture/fracture.py`, `tests/blender/test_voronoi_properties.py`. Downstream effect is cosmetic and structural rather than physical: mass, inertia, and conservation are unaffected.

**Blueprint Disposition: IMPL_SHOULD_CHANGE.** D09-S5.2 is right about what it wants. The likely fix is a proper convex-polyhedron clip — carry each cell as an explicit half-space set and compute its polytope directly, rather than accumulating bmesh cuts — which sidesteps both the fill fragility and the boolean solver.
