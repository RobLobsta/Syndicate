# DEV-001: gdx-gltf 3.x does not exist; the pinned version is 2.3.0 from JitPack

**Date:** 2026-08-08
**Category:** spec_deviations
**Related Docs:** docs/02_technical_architecture.md#D02-S4.1, docs/08_asset_pipeline.md#D08-S4.5
**Status:** resolved

## Summary
**Resolved 2026-08-17.** The client loads and renders both vehicles through gdx-gltf 2.3.0 (DISC-046).

D02-S4.1 (D02-R1) named "gdx-gltf 3.x" as the runtime glTF importer. No 3.x release exists; the newest is 2.3.0, and gdx-gltf is published to JitPack only, never to Maven Central. The catalog pins 2.3.0 and D02-S4.1 was amended in the same commit.

## Details

Verified against the live repositories before pinning:

| Coordinate | Result |
|---|---|
| `com.github.mgsx-dev.gdx-gltf:gltf:3.0.0` (JitPack) | 404 |
| `com.github.mgsx-dev.gdx-gltf:gltf:2.3.0` (JitPack) | 200 |
| `gltf` on Maven Central | no matching artifact under any Syndicate-relevant group |

Two consequences beyond the version number:

1. **A second repository is required.** `settings.gradle.kts` declares JitPack with a content filter restricted to `com.github.mgsx-dev.gdx-gltf`. Without the filter, every unresolvable coordinate in the build would fall through to JitPack, which builds arbitrary GitHub refs on demand — a typo could resolve to something nobody reviewed.
2. **gdx-gltf 2.3.0 predates libGDX 1.14.2.** It resolves and compiles, but runtime compatibility with 1.14.2 is untested here, because nothing imports a `.glb` yet. The first code to load a model must verify morph targets specifically (D08-S4.5 chose glTF *for* morph targets), not merely that a mesh appears.

The same check found KryoNet publishes only `2.22.0-RC1`, not a final `2.22.0`. D02-S4.1 said "2.22.x" and was tightened to the exact coordinate.

## Rationale / Context
A future session pinning a dependency would re-run these lookups, get the same 404, and either invent a version, silently drop to an older one, or add JitPack without a content filter. The last is the dangerous outcome: an unfiltered JitPack repository quietly widens the supply chain for the whole build.

## Impact
`gradle/libs.versions.toml`, `settings.gradle.kts`, `game-client`, `test-environment`, and the D02-S4.1 toolchain table.

Blueprint Disposition: `DOC_SHOULD_CHANGE` — the requirement (D02-R1) named a version that was never published. D02-S4.1 is amended in the same commit as this entry, so implementation and blueprint agree at HEAD. The remaining open question is runtime compatibility of gdx-gltf 2.3.0 with libGDX 1.14.2, which is unresolved only because no asset loading code exists yet.
