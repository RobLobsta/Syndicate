# DEV-018: eight of the catalogue's messages have wire ids and no codec

**Date:** 2026-08-13
**Category:** spec_deviations
**Related Docs:** docs/10_networking_multiplayer.md#D10-S4.2, docs/10_networking_multiplayer.md#D10-S6

**Status:** active

## Summary
`MessageType` holds all twenty-one messages of D10-S4.2 with their wire ids and channels reserved.
`Messages` encodes thirteen of them. `ScoreUpdate`, `MatchPhase`, `ChatMessage`, `AdminCommand`,
`Ping`, `Pong` and `SelectVehicle` are declared and not yet written or read.


## Details
Each of the seven needs a subsystem this layer does not yet drive: a scoreboard the authority
publishes, a match-phase feed, a chat UI, an admin authentication path, and an RTT estimator that
nothing yet consumes (lag compensation, D10-S5.7, is the consumer and is also unwritten). Declaring
their ids now rather than later is deliberate — the numbering is append-only (D10-R11's protocol
version is what a change to it would cost), so reserving them keeps the eventual additions from
renumbering the messages that already ship.

An unknown or unhandled message type is dropped with one debug line on both ends, so a peer built
against a later revision degrades rather than desynchronising.

## Rationale / Context
AC-D10-3 asks for a wire-capture test that every replicated field of D10-S4.3 is sent with the
stated encoding. That test can be written today for the state path and cannot yet be written for
the match and chat paths, so it is not claimed.

## Impact

**Blueprint Disposition: IMPL_SHOULD_CHANGE.** The requirement deviated from is (D10-R3).
- `Messages` covers handshake, spawn/despawn, structural, snapshot, input, NACK, disconnect, hit
  confirmation and damage received.
- Lag compensation (D10-S5.7) and its `HitboxHistory` are not implemented at all; `HISTORY_TICKS` is
  used only for input temporal validation.
