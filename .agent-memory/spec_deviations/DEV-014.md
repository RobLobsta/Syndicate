# DEV-014: an arena's collision is generated from its bounds, not loaded from collision.glb

**Date:** 2026-08-10
**Category:** spec_deviations
**Related Docs:** docs/08_asset_pipeline.md#D08-S4.7, docs/06_physics_simulation.md#D06-S4.3, docs/04_entity_component_model.md#D04-S5.4

**Status:** resolved

## Summary
**Resolved 2026-08-17.** D08-R15a/R15b already specify both legal kinds of arena; the height field is the shipped one (DEC-069).

`ArenaFactory` builds an arena's floor and four walls as convex boxes derived from `boundsMin`,
`boundsMax` and `groundY`. D08-S4.7 gives an arena an `assets.collision` glTF file; the shipped arena
declares none, and nothing reads one.

## Details

**What the spec asks for.** `arena.json` names a `collision.glb` (D08-R14), and A404 makes a missing
one an error. Loading it needs `btBvhTriangleMeshShape` — a native type `ShapeCache` does not own,
with its own backing array and disposal ordering (D02-S5.7 rule 5), against a cache that builds convex
hulls only (D06-R8). None of that exists.

**What is built instead.** Five zero-mass bodies on the `STATIC` layer: a floor whose top face is at
`groundY`, and four walls whose inner faces are the bounds. Every number comes from the arena file,
so the arena's contract — where the floor is, where the edges are, where the kill plane is, where
vehicles start — is exactly what is authored. Replacing the boxes with a mesh later changes the
*shape* of an arena and not what any other system believes about it.

**A404 is therefore not raised.** Neither the loader nor the pipeline requires an `assets.collision`,
because requiring a file nothing can read would fail every arena for a capability the project does
not have.

**Why this is not simply "no arena yet".** Every system since Phase 2 has been simulated against a
test fixture's ground box, and the shipped vehicles' braking and cornering figures were calibrated
against its 0.9 friction. `ArenaFactory` uses the same friction and the same geometry, promoted to
content, so the figures in `VEHICLES.md` hold in a real process rather than only in a test.

## Rationale / Context
The next session to touch arenas will see `assets.collision: null` and either treat it as an
oversight to fill in — which needs a mesh nobody has authored and a shape type nobody owns — or
assume the arena is a stub. It is neither: it is a complete arena whose geometry happens to be
generated, and the generated path is worth keeping even after meshes arrive, because a box arena is
the fastest way to test a physics change against a known floor.

## Impact
`game-core` `physics` (`ArenaFactory`), `asset` (`ArenaDef`, `AssetLoader`),
`assets/arenas/arena_scrapyard_01/`, `game-server-headless` (`ServerRuntime`).

**Blueprint Disposition: BOTH_VALID.** D08-S4.7 is right that a real arena is a mesh, and a
generated-from-bounds arena is a legitimate second kind that the format should be able to express —
which it now can, through the `groundY` field added to D08-S4.7 in the same commit and an
`assets.collision` that may be null. When the mesh path lands, this deviation narrows to "the shipped
arena declares no collision mesh" rather than disappearing.
