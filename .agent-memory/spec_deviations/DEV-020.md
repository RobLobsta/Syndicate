# DEV-020: the engine's forward axis is +Z, and D00-R15 says −Z

**Date:** 2026-08-17
**Category:** spec_deviations
**Related Docs:** docs/00_master_index.md#D00-S4.4, docs/06_physics_simulation.md#D06-S5.5, docs/07_damage_destruction_model.md#D07-S5.4

**Status:** active

## Summary
D00-R15 states that a vehicle's local forward axis is **−Z**. The implementation uses **+Z**, and has
since the ray-cast vehicle was written. Both shipped cars, the Kestrel and the whole preparation
pipeline agree with the implementation; the requirement is the odd one out. This session did not
create the deviation, but relied on it, so it is recorded.

## Details

**Deviates from:** D00-R15 — "A vehicle's local forward axis is −Z … Every authored part and vehicle
asset is exported in this convention."

**What the implementation does.** `PhysicsWorld:391` calls
`controller.setCoordinateSystem(0, 1, 2)`. Bullet takes axis *indices* as `(right, up, forward)`, so
forward is index 2: **+Z**. That is the axis the vehicle actually drives along.

Three things corroborate it:

- `VehicleFactory:158` — "Wheel axle … along −X, **so +Z is forward** for a right-handed wheel."
- `manifest.weapon_block` — "`+z` is the vehicle's front … so the muzzle is at the part's `hi[2]`."
- Both cars' `import.json` yaw their raw art to face +Z, and drive correctly.

**Where it will bite.** D07-S5.4's hit-zone pseudocode reads
`forward = vehicle.transform.forwardAxis()  # -Z local (D00-R15)`. That code is not written, so the
conflict has produced no defect yet. The moment it is written against the document, every frontal hit
registers as a rear hit.

**What this session relied on.** The Kestrel's `import.json` carries `yawDeg: 0` because its raw art
already faces +Z. A reader checking that file against D00-R15 would reasonably conclude the
helicopter is backwards. It is not; it faces the same way both cars do.

## Rationale / Context
Recorded rather than resolved because the two fixes are wildly asymmetric in cost and the choice is
the user's. Amending the **document** is a one-line edit that makes it describe the game that exists.
Amending the **implementation** means re-yawing three vehicles, re-deriving every muzzle offset,
revisiting the wheel axle sign and re-capturing every reference shot — a session's work to arrive at
a game that behaves identically.

Until it is settled, **the implementation is the authority for anything that has to move**, and a new
model should be yawed nose-to-+Z, which is what `syndicate-prepare` does unaided.

## Impact
`game-core` (`PhysicsWorld`, `VehicleFactory`), `blender-tool` (`manifest.weapon_block`), and all
three vehicles' `import.json`. Also the Eclipse's `SOURCE.md`, whose prose cites D00-R16 for a claim
about forward and states the convention as "+Z forward" — right about the number, wrong about the
requirement.

**Blueprint Disposition: DOC_SHOULD_CHANGE.** D00-R15 should say +Z, D07-S5.4's comment should follow
it, and the Eclipse's `SOURCE.md` sentence should be corrected. Nothing else moves.
