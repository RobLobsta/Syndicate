# DEV-007: TestWorld builds its own Bullet world at 0.005 m, not via PhysicsWorld.create

**Date:** 2026-08-08
**Category:** spec_deviations
**Related Docs:** docs/14_test_environment.md#D14-S5.5, docs/06_physics_simulation.md#D06-S5.1

**Status:** active

## Summary
D14-R10 requires the harness to construct its Bullet world through `game-core`'s `PhysicsWorld.create()`, and D06-R13 fixes the convex collision margin at 0.01 m. `test-environment`'s `TestWorld` does neither: it builds its own world and uses 0.005 m.

## Details

**Deviates from:** D14-R10 (AC-D14-10) and D06-R13.

**How it got here:** `TestWorld` was written before `PhysicsWorld` existed, so there was nothing to construct through. `PhysicsWorld.create()` now exists, so the gap is a real divergence rather than an ordering artefact.

**What differs today:**

| | `PhysicsWorld` (D06-S4.1) | `TestWorld` |
|---|---|---|
| Convex margin | 0.01 m (D06-R13) | 0.005 m, documented in the class as a deliberate choice |
| Solver iterations | 10, set explicitly | Bullet default |
| Split impulse / ERP / solver mode | Set per D06-S4.1 | Bullet defaults |
| Gravity | `WORLD_GRAVITY` | `WORLD_GRAVITY` (the one thing they agree on) |

The margin difference is the one that matters: it is the distance a resting shard sits above the ground, and the harness's physics checks measure exactly that. A fixture that verifies at 0.005 m is not evidence about a game that runs at 0.01 m, which is the whole point D14-R10 exists to protect.

**Not fixed in this session** because `test-environment` compiles only with gdx-gltf, which resolves from JitPack alone, and JitPack is blocked by this environment's egress policy. The refit is mechanical — `TestWorld` holds a `PhysicsWorld` and delegates construction, gravity and stepping to it — but it cannot be compiled or run here, and D12-R4's "don't push to test" applies.

## Rationale / Context
Both halves are invisible until they matter. The margin shows up as a half-centimetre disagreement between a harness capture and the game, which reads as a rendering offset rather than as two different physics configurations. And a future session that adds a solver setting to `PhysicsWorld` will assume the harness inherited it, because D14-R10 says it does.

## Impact
`test-environment/src/main/java/dev/syndicate/verify/physics/TestWorld.java`; every PHYS-* and PROG-* check that measures a rest height or a settle time.

**Blueprint Disposition: IMPL_SHOULD_CHANGE.** The documents are right and consistent with each other; `TestWorld` should delegate to `PhysicsWorld.create()` and take the 0.01 m margin with it. The follow-up needs JitPack reachable so `:test-environment:test` and `:test-environment:verifyFixtures` can re-run — the fixtures' rest-height expectations shift by 5 mm when the margin doubles.
